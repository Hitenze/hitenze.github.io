Login Nodes: Your Gateway to the Cluster

Purpose and Function

Login nodes serve as the access point to the cluster, providing a command-line interface for users to interact with the HPC system. They are shared resources designed for light computational tasks and job management.

Typical Specifications:

CPU Cores: 8-16 cores
Memory: 32-128 GB RAM
Storage: Limited local disk
Network: High-speed interconnect

Appropriate Activities

File Management

Upload, download, and organize research data and code

Code Development

Edit source code, compile programs, and debug applications

Job Submission

Submit, monitor, and manage computational jobs

⚠️ Critical Rule:

Never run computational jobs directly on login nodes. These shared resources are not designed for intensive computations and doing so can impact other users.

Compute Nodes: The Computational Workhorses

Standard Compute Nodes

Typical Configuration:

CPU Cores: 24-128 cores
Memory: 128-512 GB RAM
Architecture: x86_64 (Intel/AMD)

Typical role: General‑purpose compute.

GPU Nodes

Accelerated computing for parallel workloads

GPUs: 1-8 per node
GPU Memory: 16-80 GB per GPU
Best For: ML, AI, CUDA apps

High-Memory Nodes

Large-scale data processing capabilities

Memory: 1-4 TB RAM
CPU Cores: 48-256 cores
Best For: Big data, genomics

Storage Hierarchy: Understanding Data Management

HPC systems employ a hierarchical storage architecture designed to balance performance, capacity, and data safety. Understanding each tier is crucial for effective data management.

/home Directory

Characteristics:

  • • Size: 10-50 GB quota
  • • Backup: Daily backups
  • • Access: Private to user
  • • Performance: Standard I/O

Best For:

  • • Source code and scripts
  • • Configuration files
  • • Small datasets
  • • Important research documents

/scratch Directory

Characteristics:

  • • Size: 1-10 TB quota
  • • Backup: No backups
  • • Cleanup: Auto-purged (30-90 days)
  • • Performance: High-speed I/O

Best For:

  • • Temporary computation data
  • • Job input/output files
  • • Large intermediate datasets
  • • High I/O applications

⚠️ Data not backed up and may be deleted!

/project Directory

Characteristics:

  • • Size: 100 GB - 10 TB
  • • Backup: Weekly backups
  • • Access: Team shared
  • • Retention: Long-term

Best For:

  • • Shared research datasets
  • • Collaborative project files
  • • Published results
  • • Long-term data archives

Storage Best Practices

✅ DO:

  • • Keep code and small files in /home
  • • Use /scratch for active computations
  • • Move important results to /project or local storage
  • • Monitor your quota usage regularly
  • • Clean up /scratch frequently

❌ DON'T:

  • • Store large datasets in /home
  • • Rely on /scratch for permanent storage
  • • Ignore quota warnings
  • • Run I/O intensive jobs from /home
  • • Forget to backup important data

High-Speed Interconnects: The Cluster's Nervous System

The interconnect network is crucial for parallel computing performance, enabling rapid communication between compute nodes and access to shared storage systems.

Ethernet

General‑purpose, affordable networking; fine for management and non‑latency‑sensitive work.

Use it for:

  • • Login/SSH
  • • File transfers
  • • Batch jobs that don’t chat much

InfiniBand

HPC‑class RDMA with very low latency and high bandwidth; great for node‑to‑node coordination.

Use it for:

  • • MPI simulations
  • • Tightly coupled parallel codes
  • • Distributed training

NVLink / NVSwitch

Ultra‑fast links inside a server between GPUs (and sometimes GPU↔CPU on newer systems).

Use it for:

  • • Multi‑GPU jobs exchanging tensors each step
  • • Deep‑learning training
  • • GPU‑heavy solvers
