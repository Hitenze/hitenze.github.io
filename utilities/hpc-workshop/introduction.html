Introduction to High-Performance Computing

Understanding why HPC is essential for modern research and the fundamental concepts of parallel computing

Why HPC Matters for Research

Computational-Intensive Problems

Research problems requiring extensive mathematical calculations, simulations, or modeling that would take days, weeks, or months on a personal computer.

Research Examples:

  • • Climate modeling and weather prediction
  • • Molecular dynamics simulations
  • • Finite element analysis (FEA)
  • • Computational fluid dynamics (CFD)
  • • Monte Carlo simulations

HPC Solution:

Parallel processing reduces computation time from weeks to hours, enabling rapid iteration and parameter exploration.

Data-Intensive Problems

Research involving massive datasets that exceed the memory and storage capacity of typical workstations, requiring distributed processing and analysis.

Research Examples:

  • • Genomic sequencing and bioinformatics
  • • Astronomical survey data analysis
  • • High-energy physics experiments
  • • Machine learning on large datasets
  • • Social network analysis

HPC Solution:

Distributed memory systems and parallel I/O enable processing of terabyte-scale datasets that cannot fit on single machines.

Serial vs. Parallel Computing

Serial Computing

SERIAL

Instructions executed sequentially, one at a time, on a single processing unit.

Task A → Task B → Task C

Parallel Computing

PARALLEL

Multiple instructions executed simultaneously across multiple processing units.

Task A ∥ Task B ∥ Task C

Key Concepts:

Decomposition: Breaking problems into independent subtasks
Load Balancing: Distributing work evenly across processors
Synchronization: Coordinating parallel execution and data access

Core concept / scaling limit

Amdahl's Law

Parallel hardware accelerates only the part of a program that can run concurrently. If a fraction f is parallel and the rest is serial, the ideal speedup on N workers is

S(N) = 1 / ((1 - f) + f / N)

Example

With 95% parallel work and 32 workers, the ideal speedup is about 12.5x, not 32x.

Even with unlimited workers, the remaining 5% serial fraction caps speedup at 20x. Optimize the bottleneck before requesting more nodes.

Research Applications

Climate & Weather

High-resolution simulations and ensemble forecasts combine numerical models, observations, and learning-based components.

HPC role: Run many scenarios quickly enough to quantify uncertainty and support time-sensitive forecasts.

Drug & Materials Discovery

Molecular simulation, structure prediction, and large candidate searches help researchers prioritize expensive laboratory experiments.

HPC role: Evaluate many structures and parameter choices while retaining physically meaningful models.

AI/ML Training

Modern machine learning workloads distribute training, inference, and data preparation across accelerators and compute nodes.

HPC role: Balance computation, memory, and communication instead of treating more GPUs as automatic speedup.

Genomics

Genome alignment, variant calling, and population-scale analysis combine large datasets with parallel pipelines.

HPC role: Process independent samples concurrently while managing I/O and reproducible environments.

Astrophysics

N-body simulations, hydrodynamics, and telescope pipelines connect physical models with large observational datasets.

HPC role: Couple large simulations with distributed analysis and visualization.

Engineering

Computational fluid dynamics and finite-element models support design studies that would be costly to reproduce physically.

HPC role: Run parameter sweeps and high-fidelity models while tracking resource cost.

Current HPC Trends

  • Accelerator-heavy systems: CPUs coordinate work while GPUs and other accelerators provide much of the throughput.
  • Heterogeneous and mixed precision: algorithms must balance speed, memory traffic, numerical stability, and communication.
  • Energy and resource efficiency: right-sizing jobs, reducing data movement, and measuring useful throughput are core design goals.

Parallel Programming Paradigms

Shared Memory

(OpenMP)

Multiple threads within a single process share the same memory space and can access common data structures.

Characteristics:

  • • Single-node parallelization
  • • Easy data sharing
  • • Fork-join execution model
  • • Compiler directive-based
#pragma omp parallel for
for (int i = 0; i < n; i++) {
  result[i] = compute(data[i]);
}

Distributed Memory

(MPI)

Independent processes with private memory spaces communicate through explicit message passing over a network.

Characteristics:

  • • Multi-node scalability
  • • Explicit communication
  • • Process-based parallelism
  • • Network-based data exchange
MPI_Send(data, count, MPI_INT,
         dest, tag, MPI_COMM_WORLD);
MPI_Recv(buffer, count, MPI_INT,
         source, tag, MPI_COMM_WORLD, &status);

GPU Computing

(CUDA/OpenCL)

Massively parallel computing using Graphics Processing Units with thousands of lightweight cores for data-parallel workloads.

Characteristics:

  • • Thousands of cores
  • • SIMT/SIMD-style execution
  • • High memory bandwidth
  • • Specialized for data parallelism
__global__ void kernel(float *data) {
  int idx = blockIdx.x * blockDim.x
            + threadIdx.x;
  data[idx] = process(data[idx]);
}
