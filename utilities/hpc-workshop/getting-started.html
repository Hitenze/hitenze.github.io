Module 05 / Core + Reference

Getting Started: Your First HPC Job

Follow this step-by-step tutorial to run your first high-performance computing job successfully

Getting Started (VS Code path)

Local laptop checklist

  • • Stable Internet and power
  • • VS Code + “Remote – SSH” extension installed
  • • SSH available (macOS/Linux built‑in; Windows OpenSSH/WSL)
  • • Cluster details: username, host (cluster.address), MFA
  • • Optional: zip tool for large folders

VS Code quick setup

  • • Install VS Code and the “Remote – SSH” extension
  • • Connect: Ctrl/Cmd+Shift+P → Remote‑SSH: Connect to Host… → your_user@cluster.address → enter password/MFA
  • • Verify ssh your_user@cluster.address in a terminal before troubleshooting VS Code
  • • Connected when the bottom-left shows “>< SSH”
  • • Open Folder: choose the specific project directory $HOME/hpc_tutorial, not all of $HOME

File transfer

  • • Use VS Code Explorer: drag files in/out
  • • Or right‑click Upload/Download in Explorer
  • • Tip: zip large folders before upload

Field exercise 05.1 / Core

Your First HPC Job: Python

This dependency-free program confirms that Slurm placed the work on a compute node and populated the expected allocation metadata.

1

Create a project directory

$ mkdir -p "$HOME/hpc_tutorial"
$ cd "$HOME/hpc_tutorial"
$ pwd
2

Create the Python program

Save the following as hello_hpc.py, or download the reviewed example. 

#!/usr/bin/env python3
"""Small dependency-free program for a first Slurm job."""

from __future__ import annotations

import os
import platform
import socket


def slurm_value(name: str) -> str:
    """Return a Slurm value, or a useful label outside an allocation."""
    return os.environ.get(name, "not set")


def main() -> None:
    work_items = 250_000
    checksum = sum((index * index) % 97 for index in range(work_items))

    print("=== HPC environment ===")
    print(f"Hostname: {socket.gethostname()}")
    print(f"Python: {platform.python_version()}")
    print(f"Slurm job ID: {slurm_value('SLURM_JOB_ID')}")
    print(f"Slurm node list: {slurm_value('SLURM_JOB_NODELIST')}")
    print(f"CPU slots for task: {slurm_value('SLURM_CPUS_PER_TASK')}")
    print(f"Deterministic checksum ({work_items:,} items): {checksum}")


if __name__ == "__main__":
    main()
3

Create the Slurm script

Save this as hello_hpc.slurm, or download the reviewed script. Add an account, partition, or Python module only if your site requires it. 

#!/bin/bash
#SBATCH --job-name=hello_hpc
#SBATCH --output=hello_hpc_%j.out
#SBATCH --error=hello_hpc_%j.err
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=1
#SBATCH --mem=1G
#SBATCH --time=00:05:00

set -euo pipefail

# Add account, partition, and a Python module only when your site requires them.
cd "${SLURM_SUBMIT_DIR:-$PWD}"
python3 -u hello_hpc.py
Site-specific fields: do not copy an account, partition, module version, or GPU type from another cluster. Check the local quickstart first.
4

Validate, smoke-test, and inspect

Run cheap checks before asking the scheduler to execute anything.

# Shell syntax check
$ bash -n hello_hpc.slurm

# Ask Slurm to validate the request, when supported
$ sbatch --test-only hello_hpc.slurm

# Submit the five-minute smoke job
$ sbatch hello_hpc.slurm
Submitted batch job 12345

$ squeue -j 12345
$ sacct -j 12345 --format=JobID,State,Elapsed,MaxRSS,ExitCode
$ cat hello_hpc_12345.out
$ cat hello_hpc_12345.err

Success criteria

  • The job reaches COMPLETED with exit code 0:0.
  • The hostname is a compute node, not the login host.
  • The job ID, node list, and CPU allocation are populated.
  • The error file is empty.

Field exercise 05.2 / Core

Read the Evidence

Program output

=== HPC environment ===
Hostname: compute-001
Python: <site version>
Slurm job ID: 12345
Slurm node list: compute-001
CPU slots for task: 1
Deterministic checksum (250,000 items): 11999819

Exact hostnames and Python versions vary. This dependency-free smoke test intentionally uses the site's python3; use the Python 3.12 + uv workflow for project environments. The important distinction is that the program ran inside the allocation, not on the login node.

Scheduler record

$ sacct -j 12345 \
  --format=JobID,State,Elapsed,MaxRSS,ExitCode

JobID       State     Elapsed  MaxRSS  ExitCode
12345       COMPLETED 00:00:02          0:0
12345.batch COMPLETED 00:00:02 14M      0:0

Use measured elapsed time and peak memory to right-size the next request. A successful smoke job validates the path, not application scaling.

Reference 05.A / Python threads

Optional NumPy Threading Example

Use uv to lock NumPy and map one Slurm CPU allocation to the common BLAS thread controls. More threads do not guarantee faster execution; benchmark on your cluster.

Create the environment

$ uv init --python 3.12
$ uv add numpy
$ uv sync --locked
$ git add pyproject.toml uv.lock

Match allocation and threads

#SBATCH --cpus-per-task=4

export OMP_NUM_THREADS="$SLURM_CPUS_PER_TASK"
export OPENBLAS_NUM_THREADS="$SLURM_CPUS_PER_TASK"
export MKL_NUM_THREADS="$SLURM_CPUS_PER_TASK"
export NUMEXPR_NUM_THREADS="$SLURM_CPUS_PER_TASK"
uv run --frozen python -u numpy_threads.py

Download numpy_threads.py and numpy_threads.slurm. Run the environment-creation commands in the same project directory before submission. The Slurm script expects pyproject.toml and uv.lock there. Commit those two files and ignore .venv/.

Reference 05.B / Compiled code

Compiled-Code Variant

For C, C++, or Fortran, compile on the cluster with its reviewed compiler module, then run the executable in a batch allocation. Keep compilation separate from repeated production runs. 

$ module spider gcc
$ module load gcc/<site-version>
$ gcc -O2 -Wall -Wextra hello_hpc.c -o hello_hpc
$ sbatch run_compiled.slurm

Record the compiler and module versions used to build the executable. Rebuild when moving between incompatible CPU architectures or software stacks.
